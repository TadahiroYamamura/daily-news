# Dependabotのバージョン更新にデフォルトのパッケージクールダウンが導入

- URL: https://news.ycombinator.com/item?id=48913050
- 収集日: 2026-07-15
- カテゴリ: Security

## 要約

元記事: Dependabot version updates introduce default package cooldown (https://github.blog/changelog/2026-07-14-dependabot-version-updates-introduce-default-package-cooldown/)

GitHubはDependabotのバージョン更新に、デフォルトで3日間の「クールダウン」期間を導入した。新しいリリースがレジストリで公開されてから最低3日間待機してからバージョン更新のプルリクエストを作成する仕組みで、脆弱性や不具合、悪意あるコードが明らかになるまでの猶予時間を確保することが狙い。一方でセキュリティ更新（脆弱性修正）は従来通り即座に適用される。この機能はGitHub.comの全エコシステムおよびGHES 3.23以降で利用可能で、`.github/dependabot.yml`の`cooldown`オプションでカスタマイズや無効化ができる。

導入の背景には、新規パッケージリリースがサプライチェーン攻撃の代表的な侵入経路になっているという問題意識がある。悪意あるコードを含むパッケージが公開された直後に自動更新で取り込まれてしまうケースを防ぐため、短い遅延を設けることでセキュリティリサーチャーやコミュニティが不審な挙動に気づく時間を作る狙いがある。

Hacker Newsのコメント欄では賛否が分かれている。支持派は「時限爆弾型の悪意あるコードは検出リスクが高く経済的に割に合わないため、攻撃者は公開後すぐに悪用する『奪って逃げる』戦術を取ることが多く、数日の遅延でも一定の抑止効果がある」と評価する。一方で懐疑派は、クールダウン導入によって攻撃側も対応を変えてくるだけではないかと指摘し、また頻繁な依存関係更新のチャーン自体がリスク要因になる点や、セキュリティチームのアラート疲れへの懸念も挙げている。さらに、悪意あるリリースは多くの場合メンテナーが疑わしい変更パターンに気づくことで発覚しているという指摘もあり、根本的には誰でも自由にパッケージを公開できるオープンなパッケージエコシステムの構造的脆弱性が議論の核心となっている。
